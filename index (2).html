01 · Purpose and Safety

Important safety notice. MediFlow is an educational prototype, not a certified medical device. It must not be used to make clinical decisions, control an infusion, replace direct clinical observation, or provide unattended patient care. The displayed volume, flow rate, drip rate, and time estimates have not been established as clinically accurate.

What the firmware reports

  • Load-cell weight converted to an estimated remaining fluid volume.
  • Estimated remaining percentage based on the configured bag volume.
  • Estimated flow rate, drip rate, and time to empty based on recent volume readings.
  • Status messages for normal, low, critical, empty, stopped-flow, no-bag, and sensor-error conditions on the LCD and dashboard.
  • A local Wi-Fi dashboard with live device data and browser-stored demonstration records.

Required hardware

  • ESP32 DevKit
  • Load cell and HX711 amplifier
  • 16 × 2 I²C LCD (configured address 0x27)
  • ESP32 expansion board with clearly labeled D-pins
  • Push button connected to D0
  • Optional active buzzer (disabled in this firmware)
Do not rely on the dashboard or alarms as a medical safety system. Check the physical setup, the displayed values, and the sensor condition. If readings are implausible or the sensor reports an error, stop relying on the measurements and investigate the hardware.

02 · Hardware Connections

This project uses an ESP32 expansion board. Use the D-pin labels printed on the board (for example, D21), rather than searching for a header marked “GPIO 21.” The firmware uses the corresponding ESP32 GPIO numbers internally. Board labels can vary, so confirm the silkscreen and board pinout before wiring.

Load-cell capacity: The firmware defaults to a 1000 mL bag volume and 50 g for the empty bag/tubing weight. A 1000 mL bag plus its container can exceed the capacity of a 1 kg load cell. Use a load cell and mounting hardware with an appropriate rated capacity and safety margin; verify the actual assembled load. Do not exceed any component rating.

No external LEDs are required for this hardware setup. The uploaded firmware still contains LED-control code on D25, D26, and D27, but these pins are not used by the described build and no LEDs should be connected for this manual. This table is not a complete wiring diagram: connect power, ground, and the load-cell bridge according to the actual module labels and verified hardware pinout. Do not assume D-labels are identical across every ESP32 expansion board.

03 · First-Time Setup and Calibration

  1. Install the Arduino IDE and the libraries required by the sketch: HX711 and LiquidCrystal_I2C, along with the ESP32 Arduino board support.
  2. Open the uploaded mediflow_final (4)(1).ino sketch and select the correct ESP32 board and serial port.
  3. With the hook completely empty, power the device. The firmware attempts an automatic tare on first boot when the saved offset is zero. Allow the load cell to settle; the sketch's setup notes recommend about five minutes.
  4. Open Serial Monitor at 115200 baud and set the line ending to Newline.
  5. To tare manually, ensure the hook is empty and send t. Wait for the confirmation message. Do not tare with a bag or other load attached.
  6. Place a known calibration weight on the hook and send c 500 for a 500 g reference weight, or replace 500 with the actual known weight in grams. Keep the weight still while calibration completes.
  7. Send i to view the status, measured weight, estimated volume, flow values, settings, calibration factor, and dashboard address.
  8. Set the nominal bag volume using v 1000 for a 1000 mL bag, or enter the appropriate configured volume for the prototype test. Ensure the load cell and mounting can support the total load.
  9. Confirm the bag-empty weight with e 50 only if 50 g is the measured empty bag plus tubing weight. Use the actual measured value for your setup.
Calibration check: After calibration, test at more than one known weight and compare the displayed weight with an independent scale. Repeat calibration if the load cell or mount is moved or replaced. The firmware does not define a validated accuracy tolerance, so do not assume a reading is clinically accurate merely because calibration completes.

Default values in this firmware: nominal volume 1000 mL, empty bag/tubing weight 50 g, fluid density 1.015 g/mL, drop factor 20 gtt/mL, low threshold 30%, critical threshold 10%, and calibration factor 420 counts/g before calibration. These settings are saved in ESP32 flash. Verify and configure them for each test setup.

04 · LCD Status Messages

This hardware build does not use external status LEDs. Check the LCD and Wi-Fi dashboard for device status.

StatusMeaning
Normal / monitoringEstimated remaining percentage is above the low threshold and no higher-priority status applies.
LowEstimated remaining percentage is at or below the configured low threshold (default 30%), but not at critical level.
CriticalEstimated remaining percentage is at or below the configured critical threshold (default 10%).
Flow stoppedThe firmware has not detected sufficient estimated flow for the configured timeout (3 minutes).
EmptyEstimated remaining volume is 5 mL or less.
Sensor errorHX711 readings are missing or invalid/saturated for the firmware's fault criteria.
No bag / standbyThe measured weight is below the configured no-bag condition.

The LCD shows a fluid label, estimated volume, and percentage. Its second line cycles approximately every three seconds through flow rate (mL/h), drip rate (gtt/min), and estimated time to empty. Critical, stopped-flow, and empty messages can take priority over some display pages. With no bag it shows a ready message; with a sensor error it shows a sensor warning.

Interpretation: These are firmware status categories, not validated clinical alarms. The stopped-flow state is inferred from the load-cell trend and can be affected by bag movement, setup changes, and sensor noise.

05 · Daily Operation

Start monitoring a bag

  1. Check that the hook, load cell, wires, and mount are secure.
  2. Hang the bag without allowing the bag, tubing, or nearby objects to rest on another surface or pull on the load cell.
  3. Wait for the weight reading to settle and check the displayed values.
  4. Send b in Serial Monitor, or hold the button for more than 3 seconds and release it, to reset the firmware's infusion tracking for a new bag.
  5. Observe the device during prototype testing. Do not use it as a substitute for standard clinical monitoring.

Button controls

ActionFunction
Press and release for more than 50 ms and up to 3 secondsToggle the firmware mute state.
Hold for more than 3 seconds and up to 8 seconds, then releaseStart a new bag / reset infusion tracking.
Hold for more than 8 seconds, then releaseTare the empty hook. Remove the bag first.

The firmware handles button actions on release. The physical buzzer is disabled in this build, so muting does not disable the browser's independent dashboard sound setting.

Flow rate and time estimates

The firmware samples flow history every 5 seconds and retains up to 24 samples (about two minutes of history). A flow-rate estimate is based on the trend in recent estimated volume readings. It can take time for the trend to become meaningful; bag movement or a large reading change resets the analysis. Time-to-empty is an estimate, not a guaranteed prediction.

07 · Wi-Fi Dashboard

Connect in hotspot mode

  1. By default, WIFI_SSID and WIFI_PASSWORD are blank, so the ESP32 starts its own Wi-Fi hotspot.
  2. On your phone or computer, connect to Wi-Fi network MediFlow using password mediflow123.
  3. Read the IP address shown on the LCD or in Serial Monitor. In the default ESP32 access-point configuration this is commonly 192.168.4.1; use the address actually shown by the device.
  4. Open a browser on the connected device and enter http:// followed by that IP address.

Connect through a router

  1. Edit WIFI_SSID and WIFI_PASSWORD near the top of the Arduino sketch, then upload the sketch.
  2. The firmware attempts to connect for up to 12 seconds. If it cannot connect, it falls back to the MediFlow hotspot.
  3. When router mode succeeds, use the IP address shown on the LCD or in Serial Monitor. Your computer or phone must be on a network that can reach the ESP32.

Dashboard features and limitations

  • The dashboard shows the current device measurements and status and provides New bag, Mute, and Tare controls.
  • The dashboard also includes demonstration screens for ward entries, patient admission, IV history, and discharged records.
  • These patient and event records are stored in the browser's local storage, not in a centralized database on the ESP32. They may differ between browsers/devices and may be lost if browser data is cleared.
  • The dashboard's browser sound is controlled by the Sound button and is separate from the optional physical buzzer. Browser sound may require user interaction and a supported browser.
  • The firmware does not define a DEVICE_ID configuration variable. Do not follow instructions to edit one.
Privacy warning: Do not enter real patient names, diagnoses, or other identifiable health information into this educational demonstration dashboard. It is not a validated or secured hospital record system.

08 · Troubleshooting

HX711 ERROR / sensor error

Check HX711 power and ground, DOUT on D16, SCK on D4, and the load-cell wiring. Confirm the load cell is within its rated capacity and that readings are not saturated. Power-cycle only after checking wiring safely.

Weight or volume is inaccurate

Ensure the hook is empty before taring. Recalibrate with a known weight. Verify the empty bag/tubing weight, fluid density, and nominal bag volume. Compare readings against an independent scale.

Readings are unstable

Prevent the bag from swinging or touching nearby surfaces. Make sure cables and tubing do not pull on the load cell. Check the mounting and connections.

Flow says zero / ETA is --

The firmware needs a history of changing volume readings to estimate flow. Allow readings to accumulate, check for stable mechanical setup, and remember that a truly unchanging reading can produce no valid ETA.

Dashboard will not open

Confirm that your phone/computer is connected to the correct Wi-Fi network. Use the exact IP printed on the LCD or Serial Monitor and include http://. If router connection fails, the device should fall back to its hotspot.

Browser sound is silent

Press the dashboard's Sound button, check device volume, and ensure the browser allows audio. The uploaded firmware has USE_BUZZER 0, so the physical buzzer is disabled.

Alarm or status seems incorrect

Check the LCD/dashboard volume, percentage, configured thresholds, and sensor status. The firmware prioritizes sensor error, no bag, empty, critical, stopped-flow, low, then normal classification. Do not use the prototype to make patient-care decisions.

Settings seem to revert

Send i to inspect the active settings. Settings are saved to ESP32 flash; a firmware configuration-version change can reset the bag volume and empty-bag weight to defaults.

09 · Maintenance and Pre-Test Checklist

  • Inspect the hook, load-cell mount, fasteners, and wires before each prototype test.
  • Keep electronics dry and protected from spills. Disconnect power before changing wiring.
  • Never exceed the load cell, hook, or mounting hardware rated capacity.
  • Re-tare with the hook empty after moving the device, and recalibrate after moving or replacing the load cell.
  • Verify displayed weight at several known loads using an independent scale.
  • Verify that the LCD displays readings and status messages and that the Wi-Fi dashboard connects.
  • Test status transitions and dashboard sound using a controlled, non-clinical test setup.
  • Do not assume an alert works unless it has been tested. The physical buzzer is disabled in this firmware.
  • Keep a record of firmware version, calibration date, test weights, results, and any hardware changes.
Before any demonstration: Confirm that the setup is mechanically secure, the load cell is within capacity, calibration has been checked, the dashboard is connected, and everyone understands that this is a prototype only.
